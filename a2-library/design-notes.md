# Assignment 2 - Design Notes
## 1. My Fourth Item
My fourth item is an AppleLaptop, which extends LibraryItem and implements Borrowable. It has an additional field called ramGb to store its memory capacity. I chose a 7-day loan period, which is the same as a DVD and shorter than a book, because laptops are valuable and should be returned on time. The daily late fee is $3.00, meaning that a laptop returned four days late would result in a $12.00 fine, exceeding the $10.00 threshold that prevents further borrowing.
## 2. Where Loans Live
I chose to store borrowing records in a separate Loan class, where each Loan contains an item, a member, and a due day. The Library manages these records using a Loan[] array, making it easier to find and update loans. I chose this instead of storing loans inside each Member because returnItem() only receives an item ID. If loans were stored inside members, the Library would have to search through every member's loans to find the borrowed item.
## 3. Who Checks What
Although Library performs all six checks in checkOut(), each decision relies on information from different classes. For checks 1 and 2, Library uses findMember() and findItem() to determine whether the member and item exist in its arrays. For check 3, the item's type determines whether it implements Borrowable; for checks 4 and 5, Library uses findLoan() and countLoansForMember() to check whether the item is already borrowed and whether the member has reached the five-item limit. For check 6, Member stores the unpaid fine balance, and Library uses getFines() to reject borrowing only when the balance exceeds $10.00.
